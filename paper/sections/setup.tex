\section{A Testbed for Learning When to Verify}
\label{sec:setup}

\paragraph{Task.}
Each episode is an arithmetic chain $s_0 \to s_1 \to \dots \to s_d$ of depth $d$: the start value $s_0 \in \{2,\dots,6\}$ is followed by $d$ randomly sampled transitions (add, subtract, or multiply by a small constant). With probability $p_f = 0.8$, exactly one transition $h$ is \emph{faulty}: until the fault has been located, executing it applies a corrupted operation, so the agent's running value silently diverges from the true value. Conditional on a fault, $h$ is drawn from a prior that peaks in the middle of the chain. Each transition carries a one-bit \emph{cue} $c_t$ that fires with probability $0.85$ on the faulty transition and with probability $0.15$ on every other transition. The cue plays the role of a cheap, noisy signal that a reasoning step looks suspicious.

\paragraph{Actions and budget.}
The agent chooses among four actions. \texttt{THINK} executes the next transition. \texttt{VERIFY} exactly checks the most recently executed transition and returns \textsc{safe} or \textsc{unsafe}; the check is \emph{local}, so it does not detect corruption inherited from an earlier unchecked fault. The first \textsc{unsafe} result locates the fault, after which re-executing it (\texttt{REVISE}, which undoes the last step, followed by \texttt{THINK}) applies the correct operation. \texttt{COMMIT} ends the episode, which succeeds if and only if all $d$ transitions have been executed and the final value is correct. \texttt{THINK}, \texttt{VERIFY} and \texttt{REVISE} each cost one unit of a budget of $d + 6$ units. The agent can therefore afford six actions beyond the chain itself: enough to check some steps and repair one fault, but not to check every step of a long chain.

The environment is deliberately small. All quantities of interest are exact: whether a fault was present, whether and where it was caught, and which steps were checked. The question is not whether the task is hard, but whether reinforcement learning (RL) finds and keeps the right \emph{allocation} of checking effort, and whether that allocation transfers to longer chains.

\paragraph{Observations.}
The agent never observes the running value, the true value or the fault location. We compare two observation encoders (Table~\ref{tab:obs}). Both expose the local information a hand-coded checking policy needs (cue, budget slack, unchecked gap, last check result). The invariant encoder is a strict reduction of the absolute one: it replaces position and depth by two boundary flags and drops the budget fraction, so the number of remaining steps cannot be recovered from it.
\begin{itemize}
  \item \textbf{absolute} (10-d): normalised position $t/9$, depth $d/9$, budget fraction, normalised budget slack, normalised unchecked gap, cue, a revised-last-step flag and a one-hot of the last verification result. This is the encoding used in the original version of this study.
  \item \textbf{invariant} (9-d): flags for $t=0$ and $t=d$, budget slack $\mathrm{clip}(b_t-(d-t), -10, 10)/10$, unchecked gap $\min(g_t, 3)/3$, cue, the revised flag and the verification one-hot.
\end{itemize}
Here $b_t$ is the remaining budget and $g_t = t - \max(\text{checked indices})$ the number of steps executed since the highest-index checked step. Budget slack $b_t - (d - t)$ is the number of non-\texttt{THINK} actions still affordable. On held-out lengths the absolute encoding produces feature values never seen in training (for example $d/9 > 6/9$); the invariant encoding rarely does (\S\ref{sec:length}). Neither encoding gives the agent memory of earlier \textsc{unsafe} results. As a consequence, a genuine repair (\textsc{unsafe}, \texttt{REVISE}, \texttt{THINK}) and a no-op \texttt{REVISE}+\texttt{THINK} after a \textsc{safe} check lead to identical observations (\S\ref{sec:followups} adds a one-bit memory).

\section{Rewards, Learner and Reference Policies}
\label{sec:method}

\paragraph{Base reward.}
All agents receive $+1$ for a successful commit, $-1.2$ for a failed one, and $-0.04$ per unit of budget spent.

\paragraph{Process rewards.}
We compare three reward schemes, keeping the coefficients of the earlier version:
\begin{itemize}
  \item \textbf{Outcome-only}: the base reward alone.
  \item \textbf{Naive process}: $+0.015$ for each \texttt{THINK} that leaves the running value correct, and $+0.02$ for each first-time informative check. These are the kind of dense ``step is correct'' signals a process reward model provides~\citep{uesato2022process,lightman2024verify}.
  \item \textbf{Monitorability-aware} (the earlier version's name, kept for continuity): rewards checks that make the trajectory more locally diagnosable. It is a toy proxy only. The testbed has no monitor and no notion of trace legibility, so results about this reward say nothing directly about chain-of-thought monitorability:
\begin{equation}
\begin{aligned}
r^{\mathrm{MA}}_t = {}& 0.02\,\mathbf{1}[\text{safe check}] + 0.25\,\mathbf{1}[\text{fault caught}] + 0.18\,\mathbf{1}[\text{informative check},\,c_t{=}1] \\
& - 0.02\,\mathbf{1}[\text{safe check},\,c_t{=}0] - 0.06\,\mathbf{1}[\text{wasted check}] - 0.3\,\frac{g_{t+1}-g_t}{d}.
\end{aligned}
\label{eq:ma}
\end{equation}
A check is \emph{informative} if it is the first check of that step and either confirms a correct value or catches the fault. It is \emph{wasted} if it repeats a check, or checks a step downstream of an undetected fault.
\end{itemize}
Two properties of this reward, inherited unchanged from the earlier version, matter for what follows. First, the fault bonus is paid when the fault is \emph{caught}, whether or not it is then repaired. Second, the gap term telescopes to $-0.3\,g_T/d$ over an episode. It is therefore close to potential-based shaping~\citep{ng1999shaping} plus a terminal penalty that depends only on how far the last \emph{checked index} is from the end. One check of the final step cancels it, and any action that lowers $g$ is refunded, including a \texttt{REVISE} or a check that is otherwise ``wasted''. For a check downstream of a hidden fault, the refund often exceeds the $0.06$ waste penalty. The non-gap terms are not potential-based and can change the optimal policy. Both process rewards use privileged information (the hidden correctness of the running value), standing in for an accurate process reward model.

\paragraph{Learner.}
Every learned agent is a masked Double DQN~\citep{mnih2015human,vanhasselt2016double} with a 2$\times$64 ReLU MLP ($\sim$5k parameters), Huber loss, Adam (learning rate $10^{-3}$), a 25k-transition uniform replay buffer, batch size 64, a hard target update every 200 environment steps, and $\epsilon$-greedy exploration annealed linearly from 0.5 to 0.02 over the first 85\% of training. Unavailable actions are masked both when acting and in the bootstrap target. Each run trains for 20{,}000 episodes on chains of length 3--6. These are the earlier version's hyperparameters, unchanged except for $4{\times}$ more training. Before the main experiment, a two-seed pilot of the monitorability-aware agents tried six settings (two learning rates, two target-update periods, and Polyak averaging at two learning rates); we kept the original setting, which was the best in that pilot. \S\ref{sec:sensitivity} re-checks the encoder comparison under three of the alternatives with five seeds each.

\paragraph{Reference policies.}
We also evaluate four hand-coded policies that see only observable quantities. \emph{Always THINK} never checks. \emph{Verify every step} checks each new step. \emph{Cue-triggered} checks a new step if and only if its cue fired. \emph{Budget-aware} checks cued steps whenever a repair stays affordable, and also checks un-cued steps while the budget slack exceeds that requirement by a margin $m$. We pick $m{=}1$, the value that maximises success on training lengths (\texttt{scripts/tune\_heuristic.py}). All four policies repair immediately after an \textsc{unsafe} check.

\section{Evaluation Protocol}
\label{sec:protocol}

\paragraph{Seeds and episodes.}
Every learned condition is trained with 10 independent seeds. Each policy is evaluated on 500 episodes per seed and setting. Training, learning-curve validation and final evaluation draw episodes from independent random-number streams. Policies observe only depth, position, budget, cue and check results, so on training lengths the same small set of task configurations recurs in all three streams; training-length evaluation is therefore in-distribution by design, and held-out lengths are the only genuinely unseen configurations. Methods are evaluated on identical episodes for a given seed, so comparisons are paired.

\paragraph{Settings.}
We report success on training lengths (3--6), on held-out lengths 7--9, and on lengths 10--14. On 7--9 we additionally shift the fault rate ($p_f \in \{0.6, 0.9\}$), the verification cost ($c_V \in \{2,3\}$), the budget slack (4 or 8) and the cue quality (clean: $0.95/0.05$; noisy: $0.60/0.35$), without retraining.

\paragraph{Checkpoint selection.}
DQN policies on this task change abruptly during training (\S\ref{sec:stability}), so the last checkpoint is a noisy sample of what a run has learned. We greedily evaluate every agent on 200 validation episodes of \emph{training-length} chains every 1{,}000 episodes, and keep the checkpoint with the highest validation success. Held-out lengths are never used for selection; the config loader rejects any selection setting that is not the training distribution. Appendix~\ref{app:final} repeats the main results and the ablations for the last checkpoint: the encoder and reward conclusions do not change, but parity with the cue-triggered heuristic holds only for selected checkpoints (\S\ref{sec:stability}).

\paragraph{Metrics and statistics.}
Beyond success we report \emph{fault detection}, $P(\text{an \textsc{unsafe} check occurs} \mid \text{fault})$; \emph{repair completion}, $P(\text{success} \mid \text{fault detected})$; the number of \emph{non-repair} \texttt{REVISE}s (those not directly following an \textsc{unsafe} check); and \emph{cue-conditional checking}, the probability of choosing \texttt{VERIFY} at a decision point whose current step is unchecked, split by its cue $c$. The last is pooled over decision points, so a step revisited after a \texttt{REVISE} counts again. Intervals are 95\% Student-$t$ intervals of the mean over seeds; with 10 seeds a percentile bootstrap undercovers noticeably~\citep{agarwal2021precipice}. Paired differences between methods report the mean over seeds with a $t$-interval, the number of seeds favouring each method, and an exact two-sided sign-flip permutation $p$-value.
